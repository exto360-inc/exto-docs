# Dashboards & reports

Two ways to see across your records, answering different questions.

| | **Dashboard** | **Report** |
| --- | --- | --- |
| Is | A live screen of tiles and charts | A generated document |
| Answers | *How are we doing right now?* | *What exactly happened, in writing?* |
| Read | On screen, refreshed | Downloaded, filed, sent |
| Built with | The **dashboard builder** | A `.jrxml` template |

A dashboard is for watching. A report is for evidence — something to attach to
an invoice, send to a client, or keep for an audit.

## Which to build

| You want | Build |
| --- | --- |
| A number people check every morning | Dashboard |
| A trend over time | Dashboard |
| A formatted document with a letterhead | Report |
| Something to send outside the business | Report |
| A raw list to work on in a spreadsheet | Neither — [export](/work/import-export) a view |

::: tip Export is often the right answer
A saved [view](/work/views) exported to a spreadsheet answers many questions
that seem to need a dashboard, and costs nothing to set up.
:::
