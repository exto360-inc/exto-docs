# Documents

Evidence. Files attached to an asset, to a stage's records, and browsable across
the whole workbench from the **Documents** section tab.

<Shot src="cx/documents" alt="The workbench documents view" pending
  caption="Every file in the workbench, filterable by asset and stage." />

## Three places files live

| Place | Reached from | Holds |
| --- | --- | --- |
| **On the asset** | The asset's Documents tab | Files about the item itself — drawings, datasheets. |
| **On a checklist item** | Inside a [cell](/cx/completing-a-cell) | Evidence for one answer — a photo of the reading. |
| **On a linked record** | The record itself | Whatever that module holds. |

The **Documents** section tab is a view across all of them, so you can answer
"what evidence exists for this asset" without opening thirty cells.

## Browsing

The workbench documents view lists files with the asset and stage they belong
to. Filter by either, search by name, and switch between grid and table layouts.

Selecting a file opens its details — metadata, version history, and the record
or checklist item it is attached to.

## Adding files

Upload against the thing the file is evidence *for*, not into a general folder:

- Evidence for a checklist answer belongs on that **item**, where an auditor
  will look for it.
- A drawing describing the asset belongs on the **asset**.

Where a checklist item requires an attachment, the item cannot be completed
without one — the requirement is part of the [checklist](/build/checklists)
definition.

## Documents and handover

This matters more than it first appears: the [handover](/cx/handover) package
for an asset is compiled from its evidence. A file attached to the wrong thing
is a file that does not appear in the pack.

::: tip Attach evidence where it is required, not where it is convenient
A photograph dropped on the asset when the checklist item asked for it satisfies
nobody — the item stays incomplete, and the handover pack has a gap.
:::

## Relationship to Drive

CX documents are ordinary Exto documents. They live in the same collection
Drive and Photos read from, carry the same scope and version history, and an
image attached to a stage appears in [Photos](/work/documents) like any other.

The workbench view is a lens over that collection filtered to this workbench —
not a separate store.

## Permissions

Seeing a file follows the stage or asset it hangs off: a stage you cannot view
does not show you its evidence. Uploading follows **edit** on the stage. See
[Completing a cell](/cx/completing-a-cell).
