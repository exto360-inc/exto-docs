# Documents

**Drive** is the file browser over every document in the tenant. Files attached
to records, uploaded into folders, and the images that also appear in
[Photos](/work/photos) are all the same collection seen different ways.

## Browsing

Drive shows folders and files across the tenant, workspace and project scopes
you can reach. Every item carries a **scope badge** naming where it lives, so a
file's reach is visible without opening it.

Beyond folders, a **modules view** browses documents by the module they belong
to, and a **filter sidebar** narrows by type, scope, owner and date.

**Smart search** matches names, tags, document numbers and uploaders in one box.

## Working with files

| Action | What it does |
| --- | --- |
| **Upload** | Adds files to the current folder. |
| **Create folder** | Adds a folder at the current level. |
| **Check out** | Locks the file while you edit it, so two people cannot overwrite each other. |
| **Check in** | Releases the lock and stores your version. |
| **Share** | Grants people or groups access to a file or a whole folder. |
| **Link to a record** | Attaches an existing document to a record. |

::: tip Check out before editing anything shared
Downloading, editing and re-uploading without checking out is how two people end
up with two versions and no way to tell which is current.
:::

## Details and versions

Selecting a file opens its details sidebar: metadata, **version history**,
sharing, and the record it is linked to. Every replacement is a new version
rather than an overwrite, so an earlier one can always be retrieved.

## AI status

Documents indexed for the [assistant](/ai/assistant) carry a status badge —
processing, ready, or failed. Only indexed documents can be searched by the AI;
a failed one is a document the assistant cannot read.

Indexing runs as a background job. If a document sits in *processing*, see
[job status](/work/recycle-bin), where a failed job can be retried.

## Attachments on a record

The **Attachments** widget on an open [record](/work/record-widgets) is this
same system scoped to one record: upload from your device or from Google Drive,
with the same version history and metadata.

A file attached to a record is a Drive document. It appears in both places
because there is only one of it.

## Photos

Images additionally appear in [Photos](/work/photos), a gallery over the same
collection with browsing, a full-screen viewer and an edit room. Editing a photo
there saves a new version of the same document — so the change shows up in Drive
too.

## Deleting

Deleted documents and folders move to the [recycle bin](/work/recycle-bin) with
everything else, and can be restored until their retention expires.

## Permissions

Access follows the document's **scope** and the groups granted **Document
manager** at that level, plus any explicit sharing on the file or its folder.

Sharing a folder shares what it contains — which is the efficient way to grant
access, and the easy way to grant more than you meant.
